# Contributing

1. Open an issue describing the risk, control, evidence, or code change.
2. Create a focused branch and keep assumptions explicitly labeled.
3. Add or update traceability IDs; never silently renumber approved risks.
4. Use synthetic data only.
5. Run `make check` and attach relevant evidence.
6. Request review from both the technical owner and the risk-analysis owner for changes that affect conclusions.

Pull requests must state: files changed, decisions made, assumptions introduced, open questions, tests performed, and the proposed risk-register impact.
